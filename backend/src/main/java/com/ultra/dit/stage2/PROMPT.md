
На вход подается список перспективных ОКС (`List<OksObject>`). Каждый ОКС имеет:

- `String id`
- `Point connectionPoint` (целевая точка подключения)
- `Polygon buildingPolygon` (собственный полигон ОКС, тип restriction_type = "oks")
- `double flowTph` (расчетный расход, т/ч)

### ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА РЕАЛИЗАЦИЮ

Необходимо реализовать сервис `NetworkRoutingService`, который выполняет следующие шаги:

#### Шаг 2.0. Автоматическая кластеризация ОКС

Перед трассировкой сгруппируй ОКС по пространственной близости:

1. Если `connectionPoint` двух ОКС находятся на расстоянии <= 100 метров друг от друга (через `geometry.distance()`), они объединяются в один кластер. Одиночные ОКС — это кластер из 1 элемента.

#### Шаг 2.1. Локализация данных и Фильтрация (Масштабируемость)

Алгоритм не должен строить граф для всей карты во избежание OutOfMemory:

1. Для текущего кластера и потенциальных точек врезок вычисли общий минимальный охватывающий прямоугольник (Bounding Box / Envelope) с технологическим буфером **+500 метров**.
2. Через `STRtree.query(envelope)` извлеки микро-выборку объектов ограничений (`constraintsTree`), существующих сетей (`networksTree`) и камер (`nodesTree`), релевантных только для этого окна.

#### Шаг 2.2. Построение Directed Roadmap (Дискретизация пространства)

1. **Скелетизация:** Из вершин полигонов ограничений в локальном окне поиска с помощью JTS (`VoronoiDiagramBuilder`) построй оси свободных коридоров (Диаграмму Вороного). Ребра, пересекающие ограничения или нарушающие минимальный нормативный отступ, сразу отбрасывай.
2. **Структура вершин графа:** Опорные точки безопасного каркаса Вороного, точки подключения ОКС и точки существующей сети становятся вершинами ориентированного графа в JGrapht (`DirectedWeightedMultigraph`).
3. Чтобы алгоритм путевого поиска мог оценивать углы поворота, вершины графа должны хранить состояние захода:
   `VirtualNode(Coordinate coordinate, Vector2D directionIn, NodeType type)`.
4. **Ориентация графа:** Направляй ребра графа строго **ОТ существующих сетей К точкам подключения ОКС** (это обеспечит правильный ациклический обход "Назад" на следующих этапах для суммирования расходов).

#### Шаг 2.3. Матрица приоритетов углов поворота в функции стоимости (Edge Weight)

При генерации смежных ребер в графе JGrapht кастомный калькулятор весов (`EdgeWeight`) оценивает угол изменения направления Δα относительно вектора захода (`directionIn`).
Итоговый вес ребра = `Физическая длина ребра в метрах + Штраф за угол`.
Система штрафов (в метрическом эквиваленте):

- Δα = 0° (Прямая линия): Штраф = 0. (Абсолютный приоритет, исключает мелкие изломы).
- Δα = 90°: Штраф = Минимальный / Нулевой. (Наивысший приоритет стандартного поворота).
- Δα = 45°: Штраф = Низкий.
- Δα ∈ {30°, 60°}: Штраф = Средний.
- Произвольные углы <= 90° (кроме указанных выше): Штраф = Высокий (математический обход сложных препятствий).
- Углы > 90° (тупые углы и развороты назад): Штраф = Заградительный (`Double.MAX_VALUE`). Полностью блокирует движение назад.

#### Шаг 2.4. Проверка пространственных ограничений (2D Буферизация и Коллизии)

При генерации каждого сегмента (ребра графа) динамически выполняй проверку на проходимость:

1. Вокруг оси сегмента построй временный полигональный буфер радиусом **2.0 метра** (пессимистичный радиус под максимальный ДУ 1400 мм).
2. Выполни запрос: `constraintsTree.query(buffer.getEnvelopeInternal())`.
3. Для каждого найденного ограничения вычисли точное расстояние: `geometry.distance(buffer)`. Если расстояние нарушает правила отступа из ТЗ, ребро блокируется (`Double.MAX_VALUE`).
4. **ЗАЩИТА ОТ САМОБЛОКИРОВАНИЯ (Исключение из ТЗ):** Если сегмент является финальным прямым участком, заходящим внутрь собственного полигона ОКС (`buildingPolygon`), то требование отступа к **собственному полигону** этого ОКС не распространяется (в том числе на его часть в зоне отступа перед границей). Остальные чужие ограничения из индекса проверяются строго.

#### Шаг 2.5. Топологические правила и генерация до 3 вариантов

Для каждого кластера запусти алгоритм поиска кратчайшего пути (A\* или Дейкстра) по построенному графу JGrapht:

1. **Ограничение валентности:** При слиянии путей нескольких ОКС в общие участки (формирование дерева Штейнера), узел слияния помечается как `CHAMBER`. Алгоритм строго контролирует входящую и исходящую степень (degree) этого узла: если количество примыкающих линейных участков (включая разделенные существующие сети в точке врезки) достигает 4, узел блокируется для новых подключений.
2. **Разделение узлов:** Повороты без изменения параметров остаются просто вершинами внутри геометрии `LineString`. Узлы `technical_node` создаются только в точках смены атрибутов (будут использоваться далее).
3. **Генерация вариантов:** Сервис должен возвращать **до 3 содержательно отличающихся вариантов** сети для кластера (за счет использования принципиально разных коридоров или разных точек подключения к существующей сети). Небольшое смещение одной и той же трассы за отдельный вариант не считается.
4. Если из-за максимального буфера (1400 мм) пути нет, зафиксируй кластер как "неподключенный" (на этапе стоимости ему начислится штраф).
