# Этап 3. Выбор точки присоединения

Реализация: `ConnectionSelectionService`. Совместима с Java 11, JTS 1.20 и JGraphT 1.5.3 проекта.

## 3.0. Вход и связь с этапами 1–2

`newSession(indexContainer)` копирует сеть из индексов этапа 1. Поддерживаются `Feature`
(в том числе MultiLineString сети) и готовые `NetworkSegment` / `NetworkNode`.
Исходные индексы остаются доступны этапу 2 без изменения типов элементов.
Все геометрии должны находиться в одной метрической проекции, в проекте — EPSG:32637.
SRID 4326 отклоняется; SRID 0 допустим для уже преобразованных геометрий.

Этап 2 возвращает упорядоченные ребра **сеть → ОКС**. Метод `routeFromStage2`
проверяет непрерывность, собирает LineString и разворачивает его в **ОКС → сеть**.
Идентификатор ОКС передается отдельно: `RoutingResult` этапа 2 его не содержит.

## 3.1. Поиск камеры

От конечной точки строится Envelope ±10 м. После запроса STRtree кандидаты
фильтруются по типу `heat_chamber` и точному расстоянию ≤10 м, затем сортируются
по расстоянию и идентификатору. Квадрат поискового окна не заменяет круговой фильтр.

## 3.2. Проверка связности

Для каждой камеры запрос индекса сети ограничивается ее Envelope.
`line.intersects(point)` определяет число существующих участков; добавляются
подключения, ранее принятые в этой сессии. При числе ≤3 проверяется трасса
с последней координатой, замененной координатой камеры.

Обязательный `Predicate<LineString>` повторно проверяет измененную трассу на
коллизии по правилам этапа 2. Непроходимый кандидат пропускается.

## 3.3. Врезка в трубу

Если камера не выбрана, `STRtree.nearestNeighbour` ищет ближайший существующий
участок по точному расстоянию геометрий. `LengthIndexedLine.project` определяет
положение врезки; `extractLine` сохраняет промежуточные вершины трубы при разделении.
Два сегмента наследуют диаметр и parentId. Новая виртуальная камера и конец трассы
получают одну координату. Разрезание непосредственно в конце трубы не создает
нулевой сегмент: исходная труба сохраняется, создается камера на ее конце.

Нельзя обойти лимит 4 созданием виртуальной камеры поверх заполненной камеры.
Отсутствие сети, превышение лимита и непроходимая трасса возвращаются как
`IllegalStateException` без принятия подключения. Проверка не ищет вторую по
близости трубу: по ТЗ используется ближайшая.

## 3.4. Результат и топология

`ConnectionResult` содержит ОКС, тип подключения, камеру, исправленную трассу,
замененный участок и новые сегменты. После врезки STRtree перестраиваются,
поскольку построенный STRtree не поддерживает добавление элементов.
Новые подключения учитываются отдельно и не становятся кандидатами для врезки
в существующую сеть.

`buildGraph()` возвращает актуальный `DirectedWeightedMultigraph` с двумя
направлениями на участок и весом по длине. Камеры внутри линии делят ребро графа;
геометрические пересечения без камеры не считаются соединениями.
Этот граф описывает связность, а не гидравлическое направление потока.

Одна сессия соответствует одному совместно реализуемому варианту.
Альтернативы обрабатываются в разных сессиях; последовательные подключения
в одной сессии учитывают ее предыдущие изменения. Сессия не потокобезопасна.
Возвращаемые геометрии и модели следует считать доступными только для чтения.
Входные участки должны быть простыми незамкнутыми линиями, а существующая сеть —
разделенной на участки в местах подключения. Допуск привязки исходных камер к
трубам не вводится: согласно ТЗ применяется точный `intersects`.

## Пример вызова после этапа 2

```java
var session = connectionSelectionService.newSession(indices);
LineString route = connectionSelectionService.routeFromStage2(stage2Variant);
ConnectionResult result = session.connect(oks.getId(), route, adjusted ->
    collisionDetectionService.isSegmentPassable(
        adjusted, constraintsForEntireAdjustedRoute, List.of(oks)));
var graph = session.buildGraph();
```

`constraintsForEntireAdjustedRoute` — геометрии ограничений из индекса этапа 1,
выбранные по Envelope исправленной трассы с расширением на 2 м (радиус буфера
этапа 2). Предикат должен вычислять эту выборку для переданного `adjusted`.
Для нескольких ОКС передается соответствующий активный кластер.
Сервис предоставлен как отдельный этап; HTTP-конвейер `ProcessStage2RoutesService`
по-прежнему выводит результаты этапа 2. Для публикации результата этапа 3 нужны
явный выбор варианта и сопоставление результата с ОКС.

## Проверка

`mvn -o -f backend/pom.xml -Dtest=ConnectionSelectionServiceTest test`

Тесты проверяют преобразование направления, границу радиуса и круговой фильтр,
повторные подключения и лимит камеры, разрезание с сохранением длины и атрибутов,
врезку в конец трубы, отсутствие сети, изоляцию вариантов и отказ проверки коллизий.

## Публичный API

| Метод | Назначение | Изменение состояния |
| --- | --- | --- |
| `newSession(IndexContainer)` | Копирует исходную сеть и камеры, строит приватные индексы | Создает независимое состояние |
| `routeFromStage2(RoutingResult)` | Собирает упорядоченные ребра в трассу ОКС → сеть | Нет |
| `Session.connect(String, LineString, Predicate<LineString>)` | Выбирает точку присоединения и принимает подключение | При успехе добавляет трассу; при врезке обновляет сеть и камеры |
| `Session.getSegments()` | Возвращает актуальные участки существующей сети | Нет; список доступен только для чтения |
| `Session.buildGraph()` | Строит новый граф текущего состояния | Не изменяет сессию |

`getSegments()` не включает новые трассы ОКС. Это представление внутреннего списка,
а не независимый снимок: последующие врезки изменяют его содержимое.
Для фиксации списка используйте `new ArrayList<>(session.getSegments())`; геометрии
при необходимости отдельного владения также нужно копировать.
Граф строится явно вызовом `buildGraph()`, автоматически в `connect()` он не создается.

## Модели результата

| Поле `ConnectionResult` | Содержание |
| --- | --- |
| `oksId` | Переданный вызывающим кодом идентификатор ОКС |
| `connectionType` | `EXISTING_CHAMBER` либо `PIPE_TAP` |
| `chamber` | Выбранная или созданная камера |
| `route` | Полная исправленная трасса ОКС → сеть |
| `replacedSegment` | Удаленный участок при внутренней врезке; иначе `null` |
| `createdSegments` | Два заменяющих участка при внутренней врезке; иначе пустой список |

`NetworkNode` содержит `id`, `objectType`, `geometry` и `virtual`.
У новой камеры `virtual = true`, тип — `heat_chamber`, идентификатор — `virtual-<UUID>`.
При повторном использовании такой камеры результат имеет тип `EXISTING_CHAMBER`,
но флаг `virtual` остается `true`: камера уже существует в состоянии этой сессии.

`NetworkSegment` содержит `id`, `parentId`, `diameter` и `geometry`.
При повторных разрезаниях `parentId` сохраняет идентификатор первоначальной трубы.
Если диаметр в исходном `Feature` отсутствует, адаптер сохраняет `0`;
это признак отсутствующих данных, а не рассчитанный диаметр новой трубы.

Сервис использует вложенный enum `ConnectionResult.ConnectionType`.
Отдельный `stage3.types.ConnectionType` с `VIRTUAL_CHAMBER` в этом API не используется.

## Отказы и ответственность вызывающего кода

| Ситуация | Поведение |
| --- | --- |
| Результат этапа 2 не подключен, пуст или содержит разрыв порядка ребер | `IllegalArgumentException` |
| Линия пустая, нулевой длины, замкнутая, самопересекающаяся или содержит нечисловые координаты | `IllegalArgumentException` |
| У линии SRID 4326 | `IllegalArgumentException` |
| Не поддержан тип элемента индекса или геометрии сети | `IllegalArgumentException` |
| Не передан `validRoute` | `NullPointerException` |
| Камера заполнена или исправленная трасса не прошла проверку | Проверяется следующая камера |
| Камеры исчерпаны, а врезка невозможна | `IllegalStateException` |
| Валидатор выбросил исключение | Исключение передается вызывающему коду |

Не используйте текст исключения как машинный код ошибки. Для HTTP-ответа нужны
собственные статусы результата варианта и обработка ошибок в оркестраторе.
Ошибки входных данных следует отличать от отсутствия допустимого подключения.
Если несколько подключений образуют неделимый вариант, при отказе одного из них
отбросьте всю сессию: отката ранее успешных вызовов `connect()` нет.

## Геометрические и вычислительные ограничения

- Расчеты планарные, по XY. SRID сам по себе не преобразует координаты.
  Проверка SRID 4326 не доказывает, что все остальные SRID метрические;
  единая проекция гарантируется вызывающим кодом.
- Индексы должны содержать корректные ненулевые геометрии и метаданные.
  Полной проверки GeoJSON-схемы, совпадения SRID и уникальности идентификаторов здесь нет.
- Подсчитываются пересекающие точку объекты линий, а не полуребра графа.
  Камера внутри неразделенной исходной линии считается одним участком.
  Поэтому сеть перед расчетом должна быть топологически подготовлена.
- Перемещается только последняя вершина. Полная повторная трассировка,
  пересчет штрафов поворотов и ранжирование вариантов не выполняются.
- У ближайшей трубы нет предельного радиуса поиска. При равных расстояниях
  конкретный выбор трубы не гарантирован; UUID новых объектов также недетерминированы.
- Геометрические пересечения линий автоматически не узлуются. Граф делит линии
  в точках камер, а совпавшие концы линий объединяет по координатам вершин.
- Граф содержит геометрию связности и длины, но не расход, диаметр или ссылки
  ребер на `NetworkSegment`. Эти данные нужно хранить отдельно для гидравлики.

Копирование сети при создании сессии требует памяти, пропорциональной всей сети.
Поиск камер и ближайшей трубы использует STRtree; подсчет ранее добавленных
подключений проходит по списку `connections`. Каждая врезка перестраивает
приватные индексы целиком. `buildGraph()` заново обходит сеть и новые трассы,
поэтому его удобно вызывать после всех принятых подключений варианта.
