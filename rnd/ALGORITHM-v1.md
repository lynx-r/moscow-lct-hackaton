# Алгоритм пространственного анализа и трассировки тепловой сети (In-Memory, Java 11)

## Этап 1. Загрузка данных и инициализация индексов (In-Memory Pipeline)

1. **Парсинг и трансформация:**
   - Сервис принимает входной GeoJSON с клиента.
   - Геометрии парсятся в кастомные объекты `Feature` (содержащие 2D `Geometry` и `Map<String, Object> properties`).
   - С помощью GeoTools выполняется пересчет координат из исходной проекции (WGS 84) в метрическую проекцию **EPSG:32637**. Элементы с пустой геометрией (`geometry == null`) отсеиваются.

2. **Создание и наполнение индексов:**
   Инициализируются три независимых дерева `STRtree` JTS. Происходит обход коллекции трансформированных фичей, их `Envelope` вычисляется через `geometry.getEnvelopeInternal()`, а сам объект `Feature` передается в качестве метаинформации (`Item`):
   - **`constraintsTree`** — наполняется полигонами и линиями пространственных ограничений.
   - **`networksTree`** — наполняется линиями существующих тепловых сетей.
   - **`nodesTree`** — наполняется точечными объектами существующих камер, источников и точек подключения.

3. **Сборка индексов:**
   Для каждого дерева вызывается метод `build()` (или холостой запрос), чтобы JTS сформировал статический пространственный индекс в памяти до начала тяжелых расчетов.

## Этап 2. Геометрическая трассировка и поиск коллизий (Вперед)

Алгоритм последовательно обрабатывает каждый перспективный ОКС для построения до 3 вариантов новой сети:

1. **Генерация графа путей (Поиск траектории):**
   - На карте строится виртуальный граф или регулярная сетка для поиска пути (например, алгоритмом А\* или Дейкстры) от ОКС до потенциальных зон подключения.
   - Во время генерации каждого сегмента (оси будущей трубы) выполняется проверка коллизий с ограничениями.

2. **Проверка пространственных ограничений (2D Буферизация):**
   - Так как точный диаметр трубы еще не определен, вокруг оси сегмента временно строится полигональный буфер, равный **половине расчетной ширины для максимального ДУ (1400 мм)** из Таблицы 1.
   - `Envelope` этого буфера передается в `constraintsTree.query()`.
   - Из возвращенного списка ограничений для каждого элемента вычисляется точное расстояние с помощью `geometry.distance()`. Если расстояние от границы ограничения до внешней границы буфера трубы нарушает правила из Раздела 4 ТЗ, сегмент блокируется как непроходимый.

## Этап 3. Выбор точек присоединения к существующей сети

Для найденных вариантов трасс определяется точная точка врезки по алгоритму из ТЗ:

1. **Поиск существующей камеры в радиусе 10 метров:**
   - Вокруг конечной точки расчетной трассы строится `Envelope` с расширением в 10 метров.
   - Выполняется запрос `nodesTree.query(searchEnvelope)`. Из полученных точек отфильтровываются камеры (`object_type == "heat_chamber"`), расстояние до которых `\le 10` метров.

2. **Проверка связности камеры (Условие не более 4 участков):**
   - Для найденных камер-кандидатов делается запрос в `networksTree.query(cameraEnvelope)`.
   - С помощью метода `line.intersects(camera)` подсчитывается количество существующих труб, сходящихся в этой камере.
   - Если текущих труб ≤ 3, то после подключения новой трубы их станет не более 4. Камера утверждается как точка врезки. Новый участок сети завершается строго в её координатах.

3. **Врезка в тело трубы (Альтернатива):**
   - Если подходящая камера не найдена, конечная точка трассы проецируется на ближайший трубопровод из `networksTree`.
   - В этой точке создается новая виртуальная камера, существующий участок сети топологически разделяется на два сегмента, а новая труба подключается к созданной камере.

## Этап 4. Гидравлический расчет, подбор ДУ и ранжирование (Назад)

После того как геометрия оси сети построена и точки врезки определены, алгоритм выполняет расчет физических параметров:

1. **Расчет расходов и ДУ (Движение от ОКС к врезке):**
   - Алгоритм идет в обратном направлении — от конечных потребителей к точке присоединения.
   - На каждом участке разукрупнения суммируются расчетные расходы (`flow_tph`).
   - По Таблице 1 подбирается минимальный условный диаметр (ДУ), удовлетворяющий как расходу, так и предельной длине непрерывного пути. При этом контролируется правило: диаметр по направлению к точке врезки не должен уменьшаться.

2. **Расчет стоимости и ранжирование вариантов:**
   - Для каждого варианта новой сети суммируется стоимость: длина участков × цену прокладки конкретного ДУ (из Таблицы 1) + стоимость строительства новых камер/врезки.
   - Варианты ранжируются по формулам стоимости и критериям эффективности из ТЗ.
   - До 3 лучших вариантов для каждого режима упаковываются в итоговую `FeatureCollection` (в свойства элементов записываются ID, ДУ, расходы, `start_node_id`, `end_node_id` и итоговая стоимость `cost`), после чего GeoJSON возвращается клиенту.
